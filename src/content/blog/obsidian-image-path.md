把 Obsidian 当写作端、Astro 当发布端，中间隔着一个不大不小的问题：**图片**。

## 问题在哪

Obsidian 里插图，默认生成的是 wiki 链接：

```
![[screenshot.png]]
```

这是 Obsidian 的私有语法，只在它自己的生态里有效。Astro 的 Markdown 解析器根本不认，构建出来就是一段纯文本。

而标准 Markdown 是这种：

```
![](./assets/screenshot.png)
```

## 三种解法

### 方案一：装插件转换（放弃了）

社区有插件能把 wiki 链接转成标准语法。但它是在**渲染时**转换，源文件里存的还是 `![[...]]`。也就是说，你仍然在写一种只有 Obsidian 认识的格式，一旦离开 Obsidian（比如用 VS Code 打开仓库）就是一堆乱码。

### 方案二：写脚本批量替换（当备选保留）

发布前跑一个脚本，把 `![[x.png]]` 批量替换成 `![](./assets/x.png)`。

能用，但多一道工序就多一个忘记的环节。而且图片的实际存放位置还得对上，不然路径全错。

### 方案三：从源头改掉（采用）

改 Obsidian 的设置，让它**一开始就别生成 wiki 链接**：

```
设置 → 文件与链接 → 使用 Wiki 链接：关掉
                  → 新附件的默认位置：指定到下面的文件夹
```

文件夹填：

```
src/content/blog/assets
```

改完之后，粘贴图片进去，Obsidian 直接生成标准 Markdown，路径也是对的。**源文件本身在任何编辑器里都是合法的 Markdown。**

## 为什么选最笨的

方案三要多点两下设置，写的时候也不如 `![[` 顺手。但它解决的是根本问题：**文件本身是通用的**。

这一点对我很重要，因为——万一哪天 Obsidian 用不下去了、或者想换个编辑器，仓库里的几百篇 Markdown 应该是随时能拿走的资产，而不是被某个软件的私有语法锁住。

顺带还解决了一个问题：图片跟着文章放在一起，`assets/` 目录纳入版本管理，换电脑、回滚版本都不会丢。

## 剩下的注意事项

- **图片先压缩再放进去**。原文动辄几 MB 的截图直接塞仓库，clone 一次能等半天。
- 大图交给构建工具处理，不要手动去改尺寸。
- 附件目录别设成 `.obsidian` 或者仓库根目录，不然找起来很痛苦。

## 小结

| 方案 | 源文件通用性 | 需要额外操作 | 结论 |
|---|---|---|---|
| 插件渲染时转换 | 差（仍是私有语法） | 每次渲染 | 放弃 |
| 发布前脚本替换 | 好 | 每次发布 | 备选 |
| 改 Obsidian 设置 | **好** | 一次性 | **采用** |

改设置的收益不在当下，在于三年后你想搬走的时候，能直接搬走。
